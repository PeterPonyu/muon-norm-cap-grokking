# A causal norm cap preserves—and can accelerate—Muon grokking

Project page: https://peterponyu.github.io/muon-norm-cap-grokking/

## Title

A causal norm cap preserves—and can accelerate—Muon grokking

## Description

This repository holds the training runners, analysis scripts, per-run logs, and
figure rebuild for a causal Frobenius-norm cap on Muon grokking. The test asks
whether hidden-weight-norm growth is required for Muon's shortened grokking
delay. A downward-only cap on hidden-matrix norms is the intervention. Site
modules on the project page: Cap, Dose, Floor, LMC, Boundary, rebuild.

Clone: https://github.com/PeterPonyu/muon-norm-cap-grokking

Concept DOI: https://doi.org/10.5281/zenodo.21020291

## Dataset Information

Primary grokking-regime arms are synthetic. Modular addition, group composition
(including S5, the symmetric group on five elements), and the synthetic
continual-learning streams are generated by the committed runners from explicit
task parameters. Those generators are the data source; there is no separate
download for the primary arms.

The real-text boundary arm reads the public TinyStories and FineWeb-Edu
corpora. Those corpora are not bundled here. Obtain them from their public
releases if you want to rerun that arm. Cached model weights are not shipped
and are not claimed.

Recorded outputs live under `experiments/results/` as JSON / JSONL logs. Those
logs are the numbers behind the public summaries. Result logs and figures are
CC BY 4.0.

## Usage Instructions

Install Python 3.11 or newer. Create a virtual environment, then install
PyTorch for your machine (CPU or CUDA), plus `numpy`. The continuous-integration
pin file is only:

```bash
pip install -r requirements-ci.txt
```

That file covers pytest / PyYAML / jsonschema. Training additionally needs
PyTorch and numpy; those are not pinned here because the wheel depends on the
local CUDA stack.

From the repository root:

```bash
# CPU smoke for the S5 norm-cap runner
python experiments/s5_normctl/run_s5_normctl.py --smoke

# Dry-run the planned cells (no training)
python experiments/s5_normctl/run_s5_normctl.py --dry-run

# Full S5 cap grid (CUDA when a GPU is visible; long)
python experiments/s5_normctl/run_s5_normctl.py

# Analyze committed logs
python experiments/s5_normctl/analyze_normctl.py
```

Other studies follow the same pattern: `python experiments/<study>/run_*.py`.
Many runners accept `--seeds`, `--num-shards`, and `--shard-id`. Seed lists
appear in result-log filenames. Resume-aware runners skip a cell when its
log is already present.

Project-page export (optional; Node.js required):

```bash
bash portal/build.sh
```

## Methodology

Shared testbed: a two-layer transformer (~420k parameters) trained with AdamW,
Muon, and stochastic gradient descent with momentum (SGDM). The causal arm
places a downward-only Frobenius ceiling on each hidden matrix at
`k * ||W||_init`, so the projection never inflates weights and does not cancel
decoupled weight decay.

Evaluation: periodic train / validation accuracy. A run groks when validation
accuracy first crosses 0.95. The grok step is that evaluation. Fraction grokked
is the share of seeds that cross the threshold inside the step budget. Timing
comparisons use median grok step; uncertainty on ratios uses a seed-level
bootstrap 95% percentile confidence interval (CI). The real-text boundary
reports validation loss.

Steps for implementation:

1. Clone this repository (or download the Zenodo concept DOI pack).
2. Install Python 3.11+, PyTorch, and numpy. Install `requirements-ci.txt` if
   you will run tests.
3. Confirm the committed logs under `experiments/results/` if you only need to
   inspect recorded outputs.
4. Run `python experiments/s5_normctl/run_s5_normctl.py --smoke` to check the
   local stack.
5. Rerun a study with `python experiments/<study>/run_*.py` when you want new
   cells. Use `--dry-run` first.
6. Rebuild summaries with the matching `analyze_*.py` script in that study
   directory.
7. Rebuild figures only if you have the R toolchain; otherwise use the committed
   summaries.
8. Rebuild the project page with `bash portal/build.sh` only if you changed
   portal source.
